# F-Droid

The app is technically ready for [F-Droid](https://f-droid.org): it qualifies under the
[Inclusion Policy](https://f-droid.org/docs/Inclusion_Policy/), F-Droid's build server builds it from source, and
that build is byte-identical to ours, so F-Droid can publish the release APKs signed with our key
([reproducible builds](https://f-droid.org/docs/Reproducible_Builds/)).

## Eligibility

| Requirement | Status |
| --- | --- |
| Free license | MIT ([`LICENSE`](../LICENSE)), the whole repository. |
| Only free dependencies | The app's 175 runtime libraries are AndroidX, Jetpack Compose, Kotlin/kotlinx, Wire and Okio, ZXing, Guava, Dagger (from CameraX), sh.calvin.reorderable and annotation libraries, all Apache-2.0, MIT or BSD. No Google Play Services, Firebase, analytics, ads or crash reporting. QR codes are scanned with CameraX and ZXing, not ML Kit. |
| Free build tools | Gradle, the Android Gradle Plugin, Kotlin, OpenJDK. Dependencies come from Google's Maven repository and Maven Central, plugins also from the Gradle Plugin Portal. |
| No prebuilt binaries | Only `gradle-wrapper.jar`, which F-Droid's scanner removes as for every app. Images in the repository are our own; the website's platform logos (Simple Icons) aren't part of the app. |
| No tracking, no non-free network services | The app only talks to the paired computers (Bluetooth, or TCP in debug builds). The About screen links to GitHub and shares a download link, it doesn't call any API. |
| Version tags | Releases are tagged `vX.Y.Z` by the Release workflow. |
| Metadata in the repository | [`fastlane/metadata/android/en-US`](../fastlane/metadata/android/en-US): title, short and full description, icon, phone screenshots and `changelogs/<versionCode>.txt`, generated by `mise run docs` from [`docs/features.toml`](features.toml), the screenshots and `CHANGELOG.md` (the docs check fails when it's outdated). The release notes list only the app's features, fixes and performance changes (commits with the scope `android`), without authors; the first release says just that. |
| Version readable without Gradle | `version` and `version-code` are written out in [`Cargo.toml`](../Cargo.toml); the build checks that they match, `scripts/bump-version.sh` updates both. |

To discuss with F-Droid when submitting:

- **Anti-features.** None should apply. Reviewers may consider *NonFreeDep*, since the app is a remote control for
  REAPER, a proprietary (commercial) program on the computer; the extension it talks to is free (MIT) and part of
  this repository.
- **Age of the project.** The policy asks for at least three months of active development before inclusion, unless
  the app has proven users or the author already maintains apps on F-Droid. Submit once that is the case.

## Reproducible builds

- No Google-encrypted dependency metadata in the APK (`dependenciesInfo` off in `android/app/build.gradle.kts`).
- CI builds the release APK unsigned (`-Punsigned`); the Publish workflow signs it once, with `apksigner` from
  build-tools 34 (newer versions write signatures `apksigcopier` can't verify).
- The Gradle project (`android/`) isn't the root of the git repository, so the APK's VCS info is the same constant
  for every build (`NO_SUPPORTED_VCS_FOUND`), wherever it is built.
- The app has no native code and no PNG resources (vector drawables only), the usual sources of differences.

`mise run android:fdroid-check` checks all of it in F-Droid's own build server container: it builds HEAD there from
the recipe and with this machine's toolchain, compares the APKs, then signs ours with a throwaway key (like
Publish) and verifies that signature on F-Droid's build with fdroidserver, which is what F-Droid's publish step
does. The first run downloads the container image (about 1.6 GB).

## Submitting

1. Wait for the first release (step 11 of the setup), so its tag and `bandcontrol.apk` exist.
2. Get the release key's certificate fingerprint: `apksigner verify --print-certs bandcontrol.apk` (the SHA-256
   line, without colons, lower case) and put it into `AllowedAPKSigningKeys` in
   [`packaging/fdroid/dev.nikarh.bandcontrol.yml`](../packaging/fdroid/dev.nikarh.bandcontrol.yml); check the
   `Builds` entry names that release (versionName, versionCode and `commit: vX.Y.Z`; release PRs update them).
3. Run `mise run android:fdroid-check` once more.
4. Fork [fdroiddata](https://gitlab.com/fdroid/fdroiddata), copy the recipe to `metadata/dev.nikarh.bandcontrol.yml`,
   commit it as `New App: dev.nikarh.bandcontrol` and open a merge request; its CI builds the app again.

After inclusion, F-Droid's checkupdates picks up new `vX.Y.Z` tags by itself (`UpdateCheckMode: Tags`, the version
from `Cargo.toml`), builds them and publishes our APK of the same release when it matches.
