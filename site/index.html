BandControl for REAPER

Your band's REAPER, on everyone's phone.

Why not the web remote?

BandControl supersedes reaper-remote-bandui, a web page for REAPER's web interface. The page works, until you play somewhere without a usable Wi-Fi: then one phone has to share its hotspot, the computer joins it, and every musician types the computer's IP address and port into a browser, again after every reconnect.

{{icon:wifi-off}}No network setup

The computer becomes a Bluetooth device the phones connect to directly. It works in a basement, a field or a venue with a captive portal.

{{icon:qr-code}}Pair once

Scan a QR code from REAPER (or from a bandmate's phone) once. After that the app finds the computer by itself, every time.

{{icon:sliders-horizontal}}More than a mixer

Input and FOH meters with clip indicators, safe faders that don't jump when touched, and a setlist editor, in a native app that keeps the screen on.

Set up

  1. Install the extension on the computer running REAPER: quit REAPER, run the installer for your platform (on Linux copy the library, see below) and start REAPER again.
  2. Install the app on every phone: open the APK on the phone and allow installing from your browser or file manager when Android asks. A phone that has it shows a QR code for the download in its menu (About & share the app).
  3. Pair: in REAPER run the action BandControl: Show pairing QR code (Actions → Show action list). A window shows the QR code (resize it and the code grows); scan it with the app, or type the code below it.
  4. Pair the rest of the band from the first phone: menu → Share pairing with another phone.

Platform notes

{{icon:windows}}Windows

Windows 10 (1803) or newer with a Bluetooth adapter that supports the peripheral role (most built-in adapters do). The installer works without administrator rights and installs into %APPDATA%\REAPER; for a portable REAPER choose its folder. Use the ARM installer only with REAPER's ARM64EC build; an x64 REAPER running on an ARM PC needs the x64 one. Uninstall from Settings → Apps.

Until releases are signed, SmartScreen asks first: More info → Run anyway.

Manual install: copy reaper_bandcontrol-windows-x86_64.dll (or the ARM64EC one) into REAPER's UserPlugins folder (Options → Show REAPER resource path) and restart REAPER.

{{icon:apple}}macOS

macOS 10.12 or newer (11 on Apple silicon). Open bandcontrol-macos.pkg; it installs into ~/Library/Application Support/REAPER without an administrator password. Until releases are notarized, open it with right click → Open.

Manual install: copy reaper_bandcontrol-macos-universal.dylib into REAPER's UserPlugins folder (Options → Show REAPER resource path). Downloaded with a browser it is quarantined and REAPER can't load it, so once:

xattr -d com.apple.quarantine ~/Library/Application\ Support/REAPER/UserPlugins/reaper_bandcontrol-macos-universal.dylib

macOS only lets apps use Bluetooth when they declare it. If BandControl: Show status reports that REAPER lacks the Bluetooth usage description, Bluetooth can't be used from REAPER on that Mac yet.

{{icon:linux}}Linux

x86_64 or aarch64 with glibc 2.35 or newer (Ubuntu 22.04, Debian 12, Fedora 36 and newer) and BlueZ (bluetoothd), which every desktop distribution ships. Copy the .so for your architecture into ~/.config/REAPER/UserPlugins and restart REAPER. The adapter is powered on automatically.

{{icon:book-open}}REAPER versions

REAPER {{reaper_min}} or newer. Every release from {{reaper_min}} (the oldest REAPER for Linux still available) to {{reaper_tested}} passes the end-to-end tests, and every change is tested against the oldest and the newest. The extension only uses REAPER functions that are older than that; Windows and macOS use the same ones.

{{icon:android}}Android

Android 9 or newer with Bluetooth LE. The app asks for the Nearby devices permission (on Android 11 and older: location, which Android requires for Bluetooth scanning) and for the camera only when you scan a QR code. Google Play services are not needed; it works on de-Googled phones such as LineageOS.

Pairing, names and where they are saved

  • On the computer, the pairing code belongs to the REAPER installation: it is saved in REAPER's settings (its resource folder), so it is the same for every project and survives restarts. BandControl: Reset pairing key replaces it and unpairs every phone.
  • The name phones show is the computer's name unless you set one with BandControl: Set the name shown on phones, saved in the same place. Give each computer a name the band recognizes, like "Rehearsal laptop" or "Stage PC"; the app shows it at the top while connected and picks up renames automatically.
  • On the phone, the app remembers every computer it was paired with. Each REAPER installation has its own code, so the phone only finds computers it was paired with. With one of them in range it connects by itself; with several in range when the app opens it asks which one; when another one comes in range it says so and offers to switch. The menu switches between them or forgets one.

Organizing the REAPER project

BandControl finds its way around your project by a naming convention, not by guessing from the routing. Three folders, named the way it expects, decide what shows up in which tab:

INPUTS/             → Inputs tab: one track per input
FOH OUT/            → FOH tab: front of house, feeds to the house desk or the PA
IEM OUT/            → IEM tab: one mix per musician, a hardware output receiving what they want to hear
  • Songs are regions that don't overlap. Markers inside a region are the song's parts for previous / next. Most bands need none.
  • Inputs: the tracks in a top level folder with the word Input or Inputs in its name, in any case.
  • FOH (front of house: what the audience hears, through the house desk or straight to the PA): the tracks in a top level folder with the word FOH or PA in its name.
  • In-ear mixes: tracks with a hardware output and receives, in a folder with IEM or Monitor in its name. The IEM tab sets the mix's volume and the volume and mute of every receive.

Everything else is up to you: the click, backtracks, buses and any other tracks can live anywhere, organized however you like, as long as they don't land in these folders: a direct child of the Inputs or FOH folder shows up in that tab, and a track with a hardware output and receives inside the IEM folder is listed as a mix. Without these folders the Inputs and FOH tabs are hidden and the IEM tab lists every track with a hardware output and receives. There is nothing to install in the project.

Verifying downloads

Each release has a SHA256SUMS file signed with the project's key (public key):

gpg --import signing-key.asc
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
