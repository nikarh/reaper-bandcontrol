# reaper-bandcontrol — plan & progress

Goal: replace the Wi-Fi/web based `reaper-remote-bandui` with

1. a cross-platform REAPER extension (Rust) that turns the PC into a BLE GATT peripheral, and
2. an Android app (Kotlin + Jetpack Compose) that connects to it, authenticates and shows the
   **Control** and **Mix (IEM balance)** tabs.

Status legend: `[ ]` todo, `[~]` in progress, `[x]` done, `[-]` dropped/deferred.

## Protocol (v1)

### GATT layout

* Service UUID: `b4d0xxxx-...` derived from the pairing secret (so the phone scan-filters exactly its
  own PC; works on every OS because every OS can advertise a 128-bit service UUID).
* Characteristics (fixed UUIDs):
  * `rx`  – write / write-without-response, phone → PC packets
  * `tx`  – notify, PC → phone packets

### Packets & framing

BlueZ cannot unicast notifications (a notification goes to every subscribed client), so the protocol is
designed to be broadcast-safe on every OS:

* Packet = `header (1 byte)` + payload chunk. `header bit7` = more fragments follow, `bits0..6` = channel:
  * `0` broadcast (encrypted with group key, explicit counter)
  * `1..=126` unicast to session id (encrypted with that session's key, implicit counter)
  * `127` plaintext handshake
* Message = concatenation of chunks until a packet with bit7 = 0. Fragments of one message are never
  interleaved with another message on the same channel stream. Max chunk = negotiated MTU − 3 − 1.
* Client → server packets use the same format (channel = own session id / 127 for handshake).

### Security

* Pairing secret: 16 random bytes generated by the extension, stored in REAPER ExtState.
  Shown as a QR code (`bandcontrol://pair?s=<base32>&n=<name>`) — the phone camera opens the app via
  deep link; manual code entry as fallback. Rotating the secret revokes all phones.
* Handshake (mutual, challenge/response, HMAC-SHA256, keys via HKDF-SHA256):
  1. C→S `Hello { version, client_nonce[16], mtu }`
  2. S→C `Challenge { client_nonce_echo, session_id, server_nonce[16], server_proof }`
  3. C→S `Auth { client_proof }` (only after verifying `server_proof`)
  4. S→C unicast encrypted `Welcome { group_key, ... }` followed by the full `State`.
* After auth every message is ChaCha20-Poly1305 encrypted. Directional session keys, counters as nonces
  (no replay). Broadcast frames use the group key with an explicit 64-bit counter.
* Failed auth → `AuthFailed` and disconnect; handshake timeout 10 s; failed-attempt backoff.

### Messages (protobuf, `proto/bandcontrol.proto`)

* Server → client: `Welcome`, `State` (full: tracks, receives, regions, markers, region order),
  `Transport` (play state, position ms, repeat, record), `GainDelta` (only changed track/receive
  volumes/mutes), `Meters` (optional, subscription based, later).
* Client → server: `Play/Pause/Stop/Record/ToggleRepeat`, `GotoRegion`, `GotoMarker`,
  `SetTrackVolume`, `SetReceiveVolume`, `SetReceiveMute`, `SetRegionOrder`.
* Tracks are addressed by server-assigned stable ids (per GUID), receives by `(dest, index, src)`
  so a stale command never hits the wrong control.

### Update policy (Engine)

* On auth: full `State` + `Transport`.
* `Transport`: every 1 s, immediately on play-state change or seek (position jump).
* Gains: polled every timer tick, changes coalesced per tick into one `GainDelta`.
* Structure (tracks/receives/regions/markers/region order): change detected → full `State` after 1 s
  of quiet (trailing debounce, max wait 3 s).

## Log / notes

- PC BT controller supports peripheral role (BlueZ, 12 adv instances). Phone: OnePlus 8T, Android 15 (SDK 35).
- REAPER 7.82 at `/usr/lib/REAPER`. `cage` + Xwayland available for headless runs (no Xvfb, no sudo).
- `ble-peripheral-rust` rejected: one notify writer per characteristic (single client only) and spawns a task per
  notification (no ordering) → own BLE layer.
- BlueZ 5.87 here: `AcquireWrite`/`AcquireNotify` sockets are per device (checked in `gatt-database.c`), so the BlueZ
  transport is true unicast; the broadcast-safe protocol still matters for other stacks.
- mise `android-sdk` (vfox) plugin is broken (`semver` lua module) → cmdline-tools via mise `http:` backend.
- bluer dispatches each D-Bus `WriteValue` in its own task (no ordering) → IO (socket) methods for both characteristics.
- `bandctl sim --ble` advertises fine without root.
- REAPER e2e: the real Mother Project state is asserted equal to `FakeDaw::mother_project()`, which keeps the fake
  faithful (it caught wrong marker colors in the fake). Native colors: SWELL (Linux/macOS) `0xRRGGBB`, Windows
  `0x00BBGGRR`; decoded directly in `daw.rs`.
- The extension only ticks the engine while phones are connected; the engine re-snapshots on the first join.
- Harness kills the whole process group (cage + REAPER) on drop; it never touches the user's REAPER config.
- Android: compileSdk 37 is required by current Compose; `connectGatt(settings, ...)` is API 37 only so the old
  overload is used. API 33+ GATT write calls return `BluetoothStatusCodes`, not GATT status (lint caught it).
- Faders use relative drags (no jump on tap) and keep a local value while dragging + 800 ms after release.
- Optimistic UI must expire: if REAPER reverts a phone's change within the server's 1 s debounce, the server sends
  nothing (the snapshot equals what it last published), so the app drops unconfirmed local region order after 3 s.
  Found by the phone ↔ REAPER e2e.
- REAPER's web API can't read receives (`TRACK/n/SEND/-k` returns nothing); the mute button only renders server
  state, so asserting its toggle state proves the REAPER round trip.
- macOS kills processes that touch Bluetooth without `NSBluetoothAlwaysUsageDescription` in their Info.plist, so the
  CoreBluetooth backend checks the main bundle first and reports a clear error instead. Unknown whether REAPER.app has
  the key; `bandctl` embeds its own Info.plist (`crates/bandctl/build.rs`). Neither macOS nor Windows can drop a
  central from the peripheral side: `Disconnect` forgets it, unsubscribing from TX counts as a disconnect.
